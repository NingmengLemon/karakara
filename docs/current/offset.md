# 全局偏移

`offset.py` 估计一个**全局常量**偏移：正值表示歌词偏早、需要延后，负值表示偏晚、需要提前。
`--offset` 手动指定，`--no-offset-estimate` 等价于 `--offset 0`。

## 它现在做什么

1. 从人声轨建 RMS 能量曲线（50ms 一窗，归一化到 `[0,1]`）。
2. 从 LRC 建「行首指示」曲线：**只在每行时间戳处**标记一个 300ms 窄窗（跳过元数据行与
   越界的行）。
3. 两级搜索（粗 200ms / 精 50ms），打分是**分母固定的判别式对比度**：行首窗内平均能量减去
   其余位置平均能量，被推出音频范围的行首窗按 0 计入；平局取绝对值更小的偏移量。

## 自动估计必须过两道校验

任何一道不通过就**按不偏移处理**，并打印一条可以直接复制的 `--offset` 命令：

1. **行区间对比度**（`validate_estimated_offset`）：估计值必须比「不偏移」更能让整段行区间
   落在人声里。
2. **首次人声锚点**（`suggest_offset_from_onset`）：与「第一次持续人声出现的位置减去第一条
   歌词行时间戳」这个物理锚点分歧超过 **2 秒**就否决。这通常意味着 LRC 与音频属于不同剪辑，
   此时**任何**全局常量偏移都是错的。

判据退化（算不出对比度、检不出人声）时**不否决**，交给另一道校验决定。手动 `--offset`
**不受任何校验约束**：用户的显式意图优先。

**为什么要这么保守**：两条判据各自都会错，而且错在不同的歌上（实测三首歌的对照表见
[records/2026-09-12-offset-criteria.md](../records/2026-09-12-offset-criteria.md)）。自动偏移
宁可不动，也不要动错，动错的代价是把整首歌的切段推离人声。

## 负时间戳是夹取，不是回退

应用偏移后若有负时间戳，`_apply_offset` 会把它们**逐个夹到 0**，而不是把整条时间轴回退。
回退会让修正彻底失效：LRC 里几乎总有一条 `[00:00.000]` 的元数据行（「作词 : xxx」），它不
参与对齐，却会把任何负偏移精确抵消，连 `--offset` 手动给的负值也会被静默丢弃。被夹住的
如果恰好是参与对齐的行，会额外告警，那是「偏移估计过大」的信号。

## 已知限制

- **LRC 与音频版本不匹配时无解。** 歌词与音频属于不同剪辑时任何全局常量偏移都不成立，需要
  人工发现：用 `--offset` 手动指定，或者先用 `--dump-dir` 看产物。锚点校验会把明显不可调和
  的情形拦下来并告警。
- **存在真实的可辨识性平台。** 密集排布的行首整体落在同一个长人声区间内时，区间内有一段
  无法区分的平台，结果由平局规则决定。行首仍落在人声里，所以对下游影响有限。
- **模型只有一个自由度。** 只有全局常量偏移，无法处理逐行漂移。

未解的部分与「换建模方式」的方向（对齐到人声**起音**而不是「能量高的地方」）记在
[records/2026-09-12-offset-criteria.md](../records/2026-09-12-offset-criteria.md) 末尾。
