## 一、为什么默认后端是 HubertFA（2026-09-13，人耳裁决）

从 qwen3 覆盖率最低的几行里取了 4 行做**立体声 A/B**（左耳 = HubertFA 的边界咔哒，
右耳 = qwen3 的边界咔哒，两声道都有人声；咔哒位置自检 100% 落在预期边界上，±2ms）。

**line 007 的裁决**（`何もない世界それは降り立つと`，片段 13.1 秒），人耳确认整段 13 秒都
在唱这一行：

| | 覆盖率 | 判读 |
|---|---|---|
| qwen3 | 6.7%（8 个词全挤在前 2 秒） | ❌ 错 |
| HubertFA | 88.8%（16 个モーラ铺满整段） | ✅ 对 |

由此定下两件事：HubertFA 的高覆盖率**不是**「连续划分」这个输出形态的副产品，而是真实的
对齐能力；qwen3 在这类被压扁的行上是**真失败**，不是「更稀疏但更准」。

同一首歌（`Cryu - 蒲公英`）跑完整流水线对照：

| | 词级 token | 每行中位 | 行内重复标签 | 行区间覆盖率 | 对齐器报告的零长度单元 |
|---|---|---|---|---|---|
| **hfa** | 167 | 10 | 0 | **100.0%** | **0 / 135（0.0%）** |
| qwen3 | 109 | 6 | 0 | 77.3% | 59 / 141（41.8%） |

两者产物都是 0 重复标签、0 零时长 token（那是合并逻辑的效果），最后一列是**对齐器原始
输出**里的零长度比例。

**没有做完整的人工标注**（BER/IOU），所以严格说「HubertFA 更准」这句话的证据强度只到
「两种结构性冲突里 HFA 对、qwen3 错」。对「默认值」这个决策够用。

## 二、扰动稳定性 V4（2026-09-18）

判据**事先定好**：行内边界漂移的**中位数 < 1 个帧移**视为稳定。一律按 **10ms** 报，
这样两个后端可以直接对照（qwen3 自己的帧移是 80ms，按它自己的口径判据会松 8 倍）。

三条口径先说清：

1. `pad±` 的漂移**先扣掉已知平移**（+100ms 片段里同一条边界理应出现在 `base+100ms`），
   否则量到的是「我加的 padding」而不是「对齐器的敏感度」。
2. 只比**行内**边界（首尾各去掉一条）；首条边界属于锚定误差，单独报。
3. 单元数变了（`drop1`/`add1`）就不做逐边界比较，改报「是否还成立」。

输入：中文 `samples/countdown_to_zero_luotianyi`（20 行）、日文 `D:\MUSIC\Cryu - 蒲公英`
（17 行）。单元格是 `中位 / p90 / 最大`（ms）：

**中文（20 行 / 139 条行内边界）**

| 条件 | HubertFA | qwen3 | 10ms 判据 |
|---|---|---|---|
| `pad+100ms` | **1 / 41 / 740** | 20 / 60 / 1060 | HFA 稳定；qwen3 不稳定 |
| `pad-100ms` | **1 / 20 / 642** | 20 / 60 / 2180 | 同上 |
| 混音 vs 分离人声 | 10 / 389 / 3312 | **0 / 640 / 1760** | 两者都远大于一个帧移 |

**日文（16–17 行 / 118–124 条行内边界）**

| 条件 | HubertFA | qwen3 | 10ms 判据 |
|---|---|---|---|
| `pad+100ms` | **1 / 13 / 122** | 60 / 2540 / 6340 | HFA 稳定；qwen3 不稳定 |
| `pad-100ms` | **1 / 12 / 110** | 60 / 420 / 6380 | 同上 |
| 混音 vs 分离人声 | **18.5 / 398 / 1643** | 1280 / 5920 / 10480 | 两者都远大于一个帧移 |

五条结论：

1. **片段边界 ±100ms 对 HFA 基本无影响**（日文中位 1ms、p90 12–13ms）。所以生产路径的
   紧切片段就是对的，**不需要**加 padding。对照之下 qwen3 在日文上中位就漂 60ms，是它自己
   80ms 量化格的 3/4：它的边界本来就在抖，而不是「量化得粗但稳定」。
2. **真正的主导变量是分离质量，不是片段边界。** 换成原始混音后两个后端的漂移都远大于帧移
   （HFA 日文中位 18.5ms / p90 398ms）。要再提高质量，优先换更好的分离模型，而不是调切段。
3. **错一个字的代价是「从错处往后全毁」。** 扰动点**之前**的边界漂移在日文上恒等于 0
   （n=51/55，最大 0ms），中文最大也只有 48ms；而错处**之后**的中位漂移 329–519ms、
   p90 约 2.1s（日文）。HFA 从左到右锚定，没有 SOFA `match` 模式那种「只取最优连续子序列」
   的容错，所以 VOCALOID 的错字与重复段落会命中这个坑，而且产物上看不出异常。
4. **「锚定误差」这个指标对 HFA 不适用**：它的输出是对整段的连续划分，首条单元边界在结构上
   就等于片段起点，于是 `pad±` 的锚定误差恒等于加进去的 100ms（实测中位 100.0）。
5. **单元粒度**：HFA 服务返回的单元是 **zh 逐字、ja 按 `pykakasi` 的词、en 按词**，不是
   音素或モーラ。音素层的统计（如「260 モーラ」）只在 TextGrid 里存在，产物里的单元数要少
   得多（`蒲公英` 那一行在产物里是 1 个单元）。

## 三、复现

```powershell
# 服务（V4 需要一个在跑）
uv run --script scripts/hubertfa_aligner_server.py            # 8788
uv run --script scripts/qwen3aligner_server.py                # 8787（对照用）

# 扰动稳定性：中文样本歌；--separate 只在缺分离人声时才需要（结果会缓存）
uv run python scripts/check_aligner_stability.py `
  --lrc samples/countdown_to_zero_luotianyi.lrc `
  --audio samples/countdown_to_zero_luotianyi.mp3 --separate

# 换后端对照：同一份输入、同一个 --out-dir，只多一个 --tag
uv run python scripts/check_aligner_stability.py `
  --lrc samples/countdown_to_zero_luotianyi.lrc `
  --audio samples/countdown_to_zero_luotianyi.mp3 `
  --aligner-backend qwen3 --tag _qwen3
```

原始边界（每行每条件的全部边界与单元文本）会落盘到 `<out-dir>/<音频名><tag>.json`，
判定可重算；度量函数在 `tests/test_aligner_stability.py` 里用手算的已知答案逐条自检过。
